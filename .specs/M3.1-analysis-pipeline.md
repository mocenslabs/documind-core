# M3.1: Analysis Pipeline Overview

## Scope

Define the architecture-level repository analysis pipeline from Repository Loader through Capability Engine. This milestone documents stage boundaries, inputs, outputs, responsibilities, and prohibited responsibilities. It establishes how the Repository Knowledge Model is produced and consumed without specifying implementation details.

The pipeline includes:

1. Repository Loader
2. Repository Snapshot
3. Discovery Engine
4. Raw Facts
5. Normalization Engine
6. Knowledge Graph
7. Query Engine
8. Semantic Analysis
9. Capability Engine

## Acceptance Criteria

The architecture documentation is accepted when it:

1. Describes all nine pipeline stages in their intended order.
2. Defines the purpose, inputs, outputs, responsibilities, and prohibited responsibilities for every stage.
3. Identifies Repository Snapshot as the stable source-of-record boundary.
4. Shows that Discovery Engine outputs traceable Raw Facts.
5. Shows that Normalization Engine converts Raw Facts into a consistent basis for the Knowledge Graph.
6. Defines Knowledge Graph as reusable Repository Knowledge with relationships, evidence, provenance, and limitations.
7. Defines Query Engine as retrieval over shared knowledge without mutation.
8. Defines Semantic Analysis as the producer of bounded, traceable Findings.
9. Defines Capability Engine as the consumer of semantic conclusions for a capability-specific result.
10. Preserves the distinction between repository source material, facts, knowledge, findings, evidence, and capability output.
11. States that the shared pipeline is provider-agnostic.
12. States that stages must preserve snapshot provenance and known limitations.
13. Avoids implementation code, pseudocode, dependency choices, and provider-specific behavior.

## Out of Scope

This milestone does not implement repository loading, snapshot collection, fact discovery, normalization, graph storage, query behavior, semantic analysis, or capability output. It does not define Python types, data schemas, persistence, APIs, user interfaces, concurrency, error-handling mechanics, or AI-provider integrations.

It also does not define README generation behavior beyond identifying it as a future Capability Engine consumer.

## Future Extensions

Future milestones may define domain contracts for each stage, discovery strategies for additional languages and repository artifacts, graph query semantics, confidence and conflict representation, incremental analysis, caching, persistence, access control, observability, and capability-specific policies.

Any extension must preserve the stage boundaries, snapshot provenance, evidence traceability, provider neutrality, and reusable Knowledge Graph established by this overview.
